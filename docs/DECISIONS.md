# Decisions

One line per methodological decision: what you chose, why, and what it changed.
Agents append here via the `/new-feature` skill; you append here by hand.

- Exclude `casual`, `registered`: they sum to `cnt` exactly. Leaky model R^2 1.000 -> honest ridge 0.583.
- Exclude `cnt_2d_bfr`: a shipped 2-day lag we cannot test the alignment of. Build our own lags instead.
- Exclude `instant`, `yr`, `days_since_2011`: time indexes let a tree predict a flat constant past 2011 and a linear model extrapolate a trend we have no grounds for.
- Split 2011 / H1 2012 / H2 2012 by date. Test set touched once, after all feature work. *Corrected 2026-11-22: not true as written. `test_beats_the_mean_baseline` asserted ridge test R^2 > 0.4 on every pytest run from the initial commit until 2026-11-22, and the Exercise 5 recommendation cites test scores. See REPORT.md, Reproducibility and corrections, item 3.*
- Report mean and persistence baselines with every score. Persistence (test R^2 0.510, MAE 840) is within 0.07 R^2 of ridge and beats it on MAE; that caveat goes in the report. *Corrected 2026-11-22 against metrics.json: the test R^2 gap is 0.126 (ridge 0.6356 vs persistence 0.5099), and the MAEs are 840.3 vs 840.1, a tie within the bootstrap range.*
- Keep `cnt_std_7` (sample std of `cnt` over d-7..d-1; `shift(1)` before `rolling(7)` on the calendar-reindexed series). Availability: every input is a count from d-7 to d-1, all known by the end of d-1, so nothing from day d goes in. Valid R^2 ridge 0.6475 -> 0.7224 (+0.075, MAE 833 -> 700), hgb 0.2185 -> 0.0977 (-0.121, MAE 1296.6 -> 1381.6); persistence 0.4507 and mean -0.9318 unchanged. *HGB corrected 2026-11-22 to the pinned scikit-learn 1.9.1; the first version (0.2368 -> 0.0964, MAE 1291 -> 1383) was run on 1.8.0. Ridge was identical in both.*
- Kept: ridge was already a stronger model, and the feature substantially improves its validation R^2 and MAE, even though it degrades HGB's performance
- 2026-11-22: Residual target for HGB (Exercise 4): train on `cnt - cnt_lag_1`, add `cnt_lag_1` back. Defensible because yesterday's demand is available at prediction time.
